## What Vastos is

A Next.js 16 (App Router, TypeScript) SaaS app: upload a floor-plan image → AI extracts rooms → user confirms/edits rooms → picks a design style → AI generates photorealistic interior renders per room → user edits/approves → a walkthrough video + PDF export is produced. India-focused (Indian design styles, room types like Pooja Room, Rupee-oriented). Zustand local-first store (`src/lib/store.ts`, persisted to localStorage) with a best-effort Supabase mirror. Supabase also provides admin-issued-only auth (no public signup).

Read `CLAUDE.md` and `AGENTS.md` in the worktree root for the full architecture writeup — both are kept up to date and are more authoritative than this document for anything about *how the code currently works*. This document is about *what happened this session* and *what's still open*.

**No test runner exists in this repo.** The actual verification suite, every time, is:
```bash
npx tsc --noEmit
npm run lint
npm run build
```
`npm run build` matters specifically because it catches client/server-boundary bugs (`"use client"` components transitively importing server-only code) that `tsc` alone misses.

## Conventions worth knowing before touching code here

- Follow `superpowers:brainstorming` → `writing-plans` → `subagent-driven-development` for anything non-trivial, per this repo's established pattern this session (skills auto-load; the `using-superpowers` skill's rule is to invoke them whenever remotely applicable). Always specify a model explicitly; an omitted model silently inherits the session's most expensive one.
- If an `Agent` dispatch fails with a session/usage-limit error, just retry on a different (typically cheaper) model rather than giving up — that's what happened with the final review above and it succeeded immediately on retry.
